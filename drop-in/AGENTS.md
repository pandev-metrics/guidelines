# Agent notes — Git Flow

Эти правила обязательны для AI-агентов и людей. Локальные хуки и серверная проверка их проверяют. Сами правила (формат ключа, env-ветки) — в `.githooks/git-flow.conf`.

## Перед работой

1. Узнай ключ задачи из трекера (`PROJ-123`). Не выдумывай ключ.
2. **До первой правки файлов** — от интеграционной ветки (`dev` / `main` — как принято в репо):

```bash
git checkout -b feature/<KEY>
```

Пример: `feature/PROJ-123`. **Без** хвоста после номера (`feature/PROJ-123-login` запрещён).
Для бага, дошедшего до прода: `bugfix/<KEY>`. Для срочного исправления прода: `hotfix/<KEY>`. Баг, найденный до релиза, — в `feature/<KEY>`.

3. Если инструмент сам создал ветку worktree (`claude/…`, `cursor/…`, `codex/…`), переименуй её **до первого коммита**: `git branch -m feature/<KEY>`.
4. Проверь: `git branch --show-current` показывает нужную ветку. Не работай на `dev` / `main` / `prod`.
5. Проверь `git config user.email`: это рабочая почта человека, от имени которого ты работаешь. Не коммить от своей учётки или служебной почты агента.

## Коммиты

- Формат первой строки: `feature/PROJ-123 - Краткое описание`.
- Ключ — тот же, что в имени ветки; другой ключ хук отклонит. Тип может отличаться (`fix`, `refactor`, `docs`, `test`, `chore`, `ci`, `style`, `release`, `bugfix`, `hotfix`).
- Коммить **только когда человек явно попросил**. Сообщение — через HEREDOC, без `--no-verify`.
- Не используй `git commit --amend` / force-push, пока человек не попросил и это не ваш свежий незапушенный коммит.

## Merge request / pull request

- Заголовок — в формате коммита: `feature/PROJ-123 - Описание`.
- Цель: интеграционная ветка (`dev`), не `prod` напрямую из feature.
- Сразу ready for review; draft — только если человек попросил.
- Не обходи хуки (`--no-verify`).

## Запрещено

- Ветка без ключа или с хвостом после ключа
- Правка файлов до того, как заведена ветка с ключом
- Коммит без `type/KEY - …` или с ключом другой задачи
- Коммит с личной или служебной почтой вместо рабочей почты человека
- Работа и пуш с `dev` / `prod` / `main` по задаче
- Угадывание ключа задачи
